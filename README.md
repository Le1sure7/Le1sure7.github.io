## 写博客

每篇文章一个文件，放在 `library/`，再把文件名（不含 `.js`）登记到 `content.js` 的 `libraryFiles` 清单。`id` 需要唯一，日期使用 `YYYY-MM-DD`，`category` 是一个分类，`tags` 是标签数组。旧文章的 `tag` 字段和 `paragraphs` 正文仍可读取。

`markdown` 字段支持标题、嵌套列表、粗体、引用、链接、图片、表格和代码块。标题自动进入文章目录，阅读时间按正文估算。有日期的文章按年月归档。首页筛选可以组合使用，点击搜索结果会打开文章并定位到第一处正文匹配。

- 代码围栏可以使用三个反引号或三个波浪号。标注 `cpp`（也支持 `c++`）、`python` 或 `javascript`（也支持 `js`）可启用语法高亮。代码块支持一键复制。
- 行内公式使用 `$E=mc^2$` 或 `\(E=mc^2\)`。独立公式使用 `$$…$$` 或 `\[…\]`。
- 图片使用 `![图片说明](assets/example.png)`，视频使用 `![视频说明](assets/example.mp4)`。可用的文件扩展名为 `.mp4`、`.webm` 和 `.ogv`，播放取决于浏览器支持的编码。站内资源路径相对于 `index.html` 和 `post.html`。
- 把自包含的 HTML、CSS 或内联 JavaScript 放进标注为 `animation` 的代码围栏。读者展开后，动画在沙盒内运行，关闭即停止。动画中的 CSS 会遵守系统的减少动态效果设置。

正文顶层内容从行首写起，列表可用空格缩进。在普通 JavaScript 模板字符串中，需要转义反斜杠、反引号和字面量插值。使用波浪号围栏可以减少转义。原始文章草稿可以放在 `Essays/`。

## 在文章中添加音乐播放器

把音频放进仓库的 `media/` 或它的子目录，再在文章的 `markdown` 字段里写下面这一行。

```md
![fil... - Ayumi.](<media/fl/Ayumi_ - fil____EG.flac>)
```

方括号内是播放器上显示的标题。路径从网站根目录的 `media/` 开始，文件名有空格时用尖括号包裹。支持识别 `.flac`、`.mp3`、`.m4a`、`.aac`、`.wav`、`.ogg`、`.oga`、`.opus` 和 `.weba`，实际能否播放取决于浏览器支持的编码。播放器由读者手动开始播放。

点击封面或时间左侧的按钮可播放或暂停。鼠标悬停喇叭可展开音量滑块，点击喇叭可静音或恢复。触屏点喇叭展开面板，使用面板内的喇叭切换静音。正文与悬浮条音量同步，默认 30%。开始播放后，正文播放器完全滚出视野时，页面下方会出现悬浮播放器。两个位置共用同一段音频和播放进度。拖动歌曲信息可移动悬浮条，缩小时改为拖动封面。拖动悬浮条上下边可调整高度，拖动左右边可调整宽度。缩到最小只显示封面，拖动任意一边可以重新展开。鼠标悬停在悬浮条上时会显示「回到播放器」。把悬浮条拖过屏幕边缘会收成拉片，鼠标悬停拉片可展开，移开后会收回。触屏点拉片可展开，点外面可收回。也可以按住拉片向屏幕内拖，把悬浮播放器拉出来。

要显示专辑封面和同步歌词，在文章对象中添加可选的 `audio` 字段。键使用 Markdown 中的音频相对路径，值可以提供 `artist`、`album`、`cover`、`lyrics` 和 `translation`。封面放在 `media/` 或它的子目录。`lyrics` 填带时间戳的 LRC 内容，直接从 `.lrc` 文件复制到模板字符串即可。双击 HTML 本地预览时也能显示歌词。可选的 `translation` 同样用 LRC 格式，使用与原歌词相同的时间戳，译文会显示在原句下方。鼠标悬停在歌词行时显示该行时间戳，移开后渐隐。点击原句或译文可跳到该时间。

```js
audio: {
  'media/example.flac': {
    artist: '演唱者',
    album: '专辑名',
    cover: 'media/example.jpg',
    lyrics: `
[00:12.50]First line
[00:16.80]Second line
`,
    translation: `
[00:12.50]第一句译文
[00:16.80]第二句译文
`
  }
},
```

发布到 GitHub Pages 时，把对应的音频、封面和文章一起提交。

GitHub Pages 直接使用仓库里的静态文件。双击 `index.html` 也能预览，渲染依赖均随站点提供。升级依赖后，运行 `npm ci` 和 `npm run build:vendor`，提交更新后的依赖锁文件和 `vendor/` 产物。

## 发布更新与网页缓存

更新网页、CSS、JS 或 `library/` 里的文章后，在 `index.html` 和 `post.html` 里把所有 `v=` 后的旧版本号替换为同一个新版本号。格式为 `YYYYMMDD-N`，例如同日第二次发布可把 `20261124-1` 改成 `20261124-2`。站内链接和文章库请求会使用新版地址。

提交后，在 GitHub 的 Actions 确认 Pages 部署成功。若浏览器还显示旧版，可以打开 `./index.html?v=20261124-2`，或在文章原地址的 `id` 后加上 `&v=20261124-2`，把示例版本号换成实际发布的值。也可以在原网址按 `Ctrl + Shift + R` 强制刷新。
